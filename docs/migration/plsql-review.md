# PL/SQL 파일 변환 비판적 검토

검토일: 2026-10-20. 대상은 이번 `.sql` 분기, PL/SQL 식별자 변환,
기존 XML 경로와의 통합, UI 결과 표시 및 파일 출력이다.
Oracle DB에 SQL을 실행하거나 객체를 생성하지 않고, 반례를 입력해 변환 결과와
경고·파일 생성 여부를 확인했다. 기존에 통과하던 정상 예제만으로는 부족했다.

## 재현한 결함과 처리

| 우선순위 | 재현 사례 / 영향 | 처리 및 검증 |
|---|---|---|
| P1 | `JOIN ... USING(ID)`의 ID가 누락되어 테이블/조회 컬럼만 바뀜 | USING 목록도 변환. 조인 양쪽의 TO-BE 이름이 다르거나 별칭 계약이 다르면 SQL 전체 보존 + 경고 |
| P1 | NATURAL JOIN의 암묵적 공통 컬럼이 이름 변경 후 달라짐 | 해당 SQL 전체 보존 + 경고. 자동으로 ON 조건을 추측하지 않음 |
| P1 | 컬럼 자체는 매핑이 없지만 `ORDERS.UNCHANGED`의 테이블은 매핑됨 | 컬럼 변환과 테이블 한정자 변환을 분리. `TB_ORDER.UNCHANGED`로 변환 |
| P1 | 로컬 레코드 `ORDERS CUSTOMERS%ROWTYPE`가 동명 테이블을 가림 | `ORDERS.ID%TYPE`를 DB 테이블이 아닌 레코드 필드로 해석. 사용자 정의 타입이라 확정할 수 없으면 참조 보존 + 경고 |
| P1 | 중첩 DECLARE / 중첩 함수에서 같은 이름의 레코드가 다른 타입을 가림 | 현재 해석기로는 전체 변수 범위를 보장할 수 없으므로 파일 전체 보존 + 경고. 중첩 구조를 지원한다고 주장하지 않음 |
| P1 | 실패한 배치에서 먼저 만들어진 임시 결과를 UI가 최종 폴더로 복사 | 명령 성공 시에만 복사. 유효 SQL 이후 인코딩 오류가 발생하는 배치로 검증 |
| P1 | 입력과 출력의 포함 관계 / 출력 심볼릭 링크로 원본 덮어쓰기 가능 | UI에서 입력·출력은 서로 포함되지 않는 경로만 허용. 모든 복사 대상의 실제 경로를 먼저 검사하여 원본/출력 경로 밖을 가리키는 링크 차단 |
| P2 | 실제 FROM에 없는 CTE 정의까지 소스로 취급하여 모호성 경고 | 실제 선택된 FROM/JOIN 소스만 컬럼 판정에 사용 |
| P2 | MERGE의 별칭 없는 UPDATE/INSERT 대상 컬럼을 소스 컬럼과 혼동 | 쓰기 대상 문맥은 MERGE 대상 테이블로 판정 |
| P2 | DB link, 대소문자를 구분하는 quoted 식별자를 무경고로 누락/치환 | 현재 지원 범위를 벗어나는 해당 SQL은 보존 + 경고 |
| P2 | qualified 이름 전체 교체 시 중간 주석 삭제 가능 | 주석이 포함된 다중 식별자 참조는 보존 + 경고 |
| P2 | DBMS_SQL.PARSE의 SQL 문자열이 그대로인데 경고 없음 | 호출 감지 후 동적 SQL 경고. 문자열 내부는 계속 변환하지 않음 |
| P2 | UI 성공 표시 + 접힌 마지막 40줄 로그 때문에 중간 경고가 보이지 않음 | 경고 시 수동 검토 필요 배너, 기본 펼침 상세 목록. 로그 미리보기와 별도로 모든 경고 표시 |
| P2 | SQL 파일 전체가 보류됐는데 Excel이 AUTO_WARN을 자동화 성공률에 포함 | PL/SQL 포함 리포트는 경고 없는 항목 비율로 표시. Oracle 컴파일 결과와 구별 |
| P2 | CLI 출력 기본 경로가 입력의 상위이면 SQL 입력까지 제외 | 생성되는 migration 하위 경로만 제외. 상위 출력 기본 경로에서도 입력 발견 검증 |

회귀 테스트: `tests/test_plsql_rewriter.py`, `tests/test_migration_ui.py`.
UI 테스트는 실제 Streamlit 스크립트를 실행하고 폴더 변환, 경고 화면,
Excel Notes, 실패 시 결과 미복사 및 원본 보존을 확인한다.
업로드 화면은 저장된 결과 상태를 주입해 경고와 다운로드 표시를 검증했다.
브라우저 파일 선택 대화상자를 통한 실제 업로드는 이번 자동 검증에 포함하지 않았다.

## UI 표시

SQL 마이그레이션 화면 상단:

> SQL 파일은 일부만 변환될 수 있습니다. AUTO_WARN이 있으면 실행 로그와
> Excel의 Conversions → Status / Notes를 확인하세요.

`동적 SQL·모호한 구문이란? (예시와 검토 방법)`을 펼치면 고정/조합 문자열
SQL과 `SELECT ID` / `SELECT o.ID` 비교, 결과 확인 순서가 표시된다.

경고가 있는 변환 결과:

> 변환 파일이 생성됐지만 수동 검토가 필요합니다. 일부 SQL·참조는 원문으로
> 남아 있을 수 있습니다.

바로 아래 `수동 검토 항목`이 펼쳐지고 파일명·원본 행 번호·사유가 보인다.
원문을 보존한 파일도 결과에 포함될 수 있으며, 다운로드 가능 여부를
컴파일 성공으로 해석하면 안 된다.

## 남아 있는 한계와 검증 범위

- 완전한 Oracle PL/SQL 파서·이름 해석기가 아니다. 정적 SQL의 식별자 위치와
  제한된 선언부 참조를 변환하는 도구다. Oracle 컴파일 성공을 증명하지 않는다.
- EXECUTE IMMEDIATE, 동적 OPEN FOR, DBMS_SQL.PARSE는 경고 후 원문 보존한다.
  임의의 사용자 정의 래퍼 함수 안에서 실행되는 동적 SQL까지 탐지하지는 않는다.
- 중첩 DECLARE/서브프로그램은 파일 전체 보존 대상으로 의도적으로 제한했다.
  사용자 정의 레코드/컬렉션 타입, 커서 SELECT *, 패키지 외부 타입과 복잡한
  이름 해석은 수동 검토가 필요하다.
- split/merge/drop/타입·값 변환은 이름 치환과 별개다. 해당 매핑은 경고하며,
  경고 파일에는 일부 참조만 바뀌어 있을 수 있다.
- 임의의 미등록 컬럼의 존재 여부와 참조 의미를 매핑 파일만으로 완전히
  검증할 수 없다. TO-BE Oracle 개발 환경에서 컴파일·대표 실행 확인이 남는다.
- Linux Python 3.12 / sqlglot 30.23.0에서 UI·회귀 테스트 103개가 통과했다.
  Windows 포터블 ZIP은 Python 3.11.9와 Windows 의존성을 포함해 생성했으며,
  의존성·바이너리 아키텍처·체크섬과 복사된 앱의 Linux 변환 동작을 검토했다.
  실제 Windows 실행 및 Oracle 11g 실환경 컴파일·실행은 검증하지 않았다.
  배포판의 `BUILD-REVIEW.txt`에 세부 범위를 기록했다. 새 ZIP에는 필요한 의존성이
  포함돼 있으며, 기존 배포판을 수동 갱신하는 경우 새 wheel 반입이 필요하다.
- 현재 테스트 통과는 위 검증 범위에 한정한다. 실제 고객 소스 전체와 실행 결과가
  확인된 것으로 해석하지 않는다.
